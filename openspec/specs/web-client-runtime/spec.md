# web-client-runtime Specification

## Purpose
Определяет границы транспорта и состояния, которые позволяют тестировать веб-клиент независимо от внешних сервисов.

## Requirements

### Requirement: Подстановка API и WebSocket

Клиент SHALL принимать API и WebSocket через независимые порты при сборке экземпляра приложения. Производственные адаптеры SHALL использовать публичные сгенерированные контракты #6 для Connect и бинарного Gateway. UI SHALL обращаться к действиям приложения, которые используют порты.

#### Scenario: Проверка сценария без сети

- **GIVEN** в каркас переданы фальшивые API и WebSocket, реальные сеть и сокет запрещены в тесте
- **WHEN** выполняется действие чтения и заглушка сокета отправляет тестовое событие
- **THEN** слой обмена вызывает переданный API и обрабатывает событие через переданный WebSocket-порт; наблюдаемое состояние обновляется

#### Scenario: Совместимость производственных адаптеров

- **GIVEN** доступны публичные дескрипторы и контрольные данные принятого #6
- **WHEN** тестовый транспорт возвращает ответ публичного RPC и бинарный GatewayEnvelope
- **THEN** API-адаптер передаёт типизированные данные или ошибку в слой обмена, а WebSocket-адаптер доставляет кадры Ready, HeartbeatAck и ServerEvent, сообщает об открытии и закрытии соединения с кодом и причиной; кадры Identify и Heartbeat от сервера, пустая оболочка и повреждённый кадр не доставляются и сообщаются как ошибка протокола

#### Scenario: Освобождение подписки

- **GIVEN** экземпляр приложения подписан на тестовый WebSocket
- **WHEN** экземпляр освобождается и порт после этого выдаёт событие
- **THEN** подписка снята, событие не изменяет состояние освобождённого экземпляра

### Requirement: Фабрика состояния на вкладку

Store SHALL создаваться фабрикой для каждого экземпляра приложения во вкладке и передаваться его представлению и слою обмена. Изменяемые сущности, подписки и начальные данные SHALL быть изолированы между экземплярами.

#### Scenario: Два экземпляра работают независимо

- **GIVEN** из одной фабрики созданы два экземпляра приложения с разными подстановками
- **WHEN** первый выбирает диалог и принимает событие
- **THEN** изменяется только первый store, а второй сохраняет своё начальное состояние

# local-environment Specification

## Purpose
Обеспечивает воспроизводимый локальный запуск контейнеров из репозитория. Основание — HLD §3.1 и §3.3 для состава системы и §6.4 для проверочного окружения.

## Requirements

### Requirement: Запуск окружения одной командой

Окружение SHALL запускать Auth, Chat, Media, Presence, Gateway, PostgreSQL, Redis, NATS Core, MinIO и Caddy документированной командой Docker Compose из корня репозитория. Backend SHALL собираться внутри контейнеров из текущих исходников. Для запуска SHALL быть достаточно работающего Docker с Compose и доступа к источникам образов и Go-зависимостей.

#### Scenario: Чистый checkout запускается без локального Go

- **GIVEN** чистый checkout без готовых backend-бинарников и локального Go, Docker с Compose доступен, используемые сетевые источники доступны
- **WHEN** выполняют команду первого запуска из README с тестовым окружением
- **THEN** backend собирается, все перечисленные долговременные контейнеры запускаются, пять сервисов отвечают на внутренние `GET /healthz` кодом `200`

#### Scenario: Ошибка сборки видима вызывающей стороне

- **GIVEN** в проверочной копии checkout исходники одного backend-процесса не компилируются
- **WHEN** выполняют документированную команду со сборкой
- **THEN** команда завершается с ненулевым кодом и сообщает об ошибке сборки, успешный запуск окружения не заявляется

### Requirement: Явная конфигурация контейнеров

Compose SHALL получать адреса, порты, credentials и имя bucket через документированное окружение, согласованное с корневым `.env.example`. Backend в контейнерах SHALL слушать `0.0.0.0`. Примеры credentials SHALL быть обозначены как тестовые. Каждая переменная SHALL иметь указанного потребителя. Значения TTL добавляются при подключении использующих их компонентов.

#### Scenario: Переопределение внешнего порта

- **GIVEN** выбран свободный внешний HTTPS-порт, отличный от значения в `.env.example`
- **WHEN** запускают окружение с этим значением
- **THEN** Caddy доступен на выбранном порту, настройки разрешаются через окружение без редактирования Compose

#### Scenario: Нужная настройка пуста

- **GIVEN** обязательная настройка bucket или credentials пуста
- **WHEN** проверяют конфигурацию и запускают окружение
- **THEN** подготовка завершается с явной ошибкой до успешной инициализации bucket, успешный запуск не заявляется

### Requirement: Сохранение данных при повторном запуске

Данные PostgreSQL, MinIO и локального удостоверяющего центра Caddy SHALL сохраняться между остановками и повторными запусками окружения. Обычная остановка SHALL сохранять volumes. Удаление данных SHALL выполняться отдельной документированной командой очистки.

#### Scenario: Контрольные данные переживают перезапуск

- **GIVEN** окружение запущено, через служебные клиенты созданы контрольная таблица PostgreSQL и объект в MinIO, сохранён отпечаток локального CA
- **WHEN** выполняют документированные остановку и повторный запуск без очистки
- **THEN** контрольная запись и объект доступны, отпечаток CA совпадает

### Requirement: Доступ к сервисам ограничен назначением

Backend, PostgreSQL, Redis и NATS SHALL быть доступны другим контейнерам по внутренней сети. Их порты SHALL оставаться неопубликованными на хост по умолчанию. Caddy и прямой S3-доступ SHALL иметь отдельно документированные внешние адреса, привязанные к loopback в локальном окружении.

#### Scenario: Прикладные сервисы доступны через входной прокси

- **GIVEN** окружение запущено с настройками по умолчанию
- **WHEN** проверяют опубликованные порты и обращаются к backend из контейнера той же сети
- **THEN** backend доступен по внутреннему адресу, его порт отсутствует среди опубликованных на хост

### Requirement: Инструкция соответствует этапу проекта

README SHALL описывать запуск, диагностику, остановку, повторный запуск, явную очистку volumes и установку доверия локальному CA. Инструкция SHALL указывать текущие ограничения веб-клиента, прикладных RPC, WebSocket, миграций, fixture и backend-readiness.

#### Scenario: Разработчик проверяет текущий каркас

- **GIVEN** чистый checkout и инструкция README
- **WHEN** разработчик выполняет описанные команды запуска и диагностики
- **THEN** наблюдаемые состояния совпадают с инструкцией, а отсутствие ещё не реализованных пользовательских сценариев объясняется принадлежностью к соответствующим карточкам

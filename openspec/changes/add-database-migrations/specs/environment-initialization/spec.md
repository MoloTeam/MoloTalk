# Environment Initialization Delta


## MODIFIED Requirements

### Requirement: Ожидание инфраструктуры перед запуском потребителей

Compose SHALL использовать проверки доступности PostgreSQL, Redis, NATS и MinIO для порядка запуска. Подготовка bucket SHALL начинаться после готовности MinIO, миграции — после готовности PostgreSQL. Пять backend-процессов SHALL запускаться после успешных обязательных инфраструктурных проверок, подготовки bucket и миграций. Caddy SHALL запускаться после успешных healthcheck пяти процессов.

#### Scenario: Инфраструктура запускается с задержкой

- **GIVEN** один из инфраструктурных контейнеров ещё проходит стартовую проверку
- **WHEN** запускают окружение
- **THEN** зависящие от него процессы ожидают успешной проверки, и порядок продолжается после её успеха

#### Scenario: Инфраструктура остаётся недоступна

- **GIVEN** инфраструктурный контейнер не проходит проверки в пределах настроенных попыток
- **WHEN** выполняют команду запуска с ожиданием состояния контейнеров
- **THEN** команда сообщает об отказе, зависимые сервисы не проходят стартовую цепочку, состояние доступно в диагностике Compose

#### Scenario: Ошибка миграции блокирует первый запуск backend

- **GIVEN** инфраструктура готова, bucket подготовлен, а одноразовая служба миграций возвращает ненулевой код
- **WHEN** выполняют первый запуск окружения
- **THEN** backend и зависящий от него Caddy не запускаются, команда сообщает ошибку подготовки БД

## ADDED Requirements

### Requirement: Подготовка схемы перед запуском backend

По HLD §4.1–4.3 и §6.4 Compose SHALL автоматически применять миграции после готовности PostgreSQL. Запуск backend SHALL зависеть от успешного завершения подготовки схемы. При повторном запуске SHALL применяться только новые версии. Fixture загружается явно в отдельную проверочную или демонстрационную БД.

#### Scenario: Новая БД получает схему до запуска сервисов

- **GIVEN** новый volume PostgreSQL и доступная инфраструктура
- **WHEN** выполняют документированную команду запуска
- **THEN** сначала миграции создают схему и завершаются успешно, затем запускаются backend и Caddy, базовая fixture автоматически не появляется

#### Scenario: Повторный запуск сохраняет данные

- **GIVEN** схема уже подготовлена и содержит контрольную запись
- **WHEN** окружение останавливают без удаления volumes и запускают повторно
- **THEN** миграции завершаются успешно без повторного DDL выполненных версий, запись сохраняется, backend запускается после завершения службы миграций

## REMOVED Requirements

### Requirement: Запуск не зависит от будущих миграций

**Reason**: Временное поведение этапа #4 заменяется автоматическим применением миграций в #5. Сценарий запуска без прикладной схемы утрачивает актуальность.
**Migration**: Использовать требование «Подготовка схемы перед запуском backend» и ожидать успешного завершения одноразовой службы миграций.

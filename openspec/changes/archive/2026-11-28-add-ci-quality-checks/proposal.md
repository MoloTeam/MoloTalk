# Proposal

## Why

На `main` нет workflow, который проверяет сборку и тесты проекта на GitHub. Issue #8 вводит повторяемые проверки Go и web и делает покрытие по ветвям видимым для команды. Основание для тестовых окружений — HLD §5.4. Прямых требований FS к CI нет.

## What Changes

- Добавить GitHub Actions workflow для Go, web и API. Запускать проверки для предложенных изменений в `main` и после обновления `main`. Для первой проверки без PR запускать CI по push ветки #8.
- Запускать существующие Go build/vet/unit, PostgreSQL-тесты с тегом `integration`, npm lint/typecheck/test/build, проверку Buf/golden и Compose-матрицу Caddy. Использовать текущие команды и версии инструментов.
- Публиковать отдельные результаты покрытия по ветвям для Go и web с описанием области измерения. Ошибки сборки, тестов и получения отчёта должны быть видны в статусах GitHub.
- Описать локальный повтор проверок. Пороги покрытия и обязательные статусы согласовать по карточке #8 и Q9 архитектурного ревью. Браузерный E2E приложения и изменение API, proto, миграций или runtime-сервисов находятся за рамками.

## Capabilities

### New Capabilities

- `continuous-integration` — автоматическая проверка репозитория и публикация результатов покрытия.

### Modified Capabilities

Действующие требования к генерации контрактов, маршрутизации, миграциям и клиенту сохраняются.

## Impact

Затронуты `.github/workflows/`, документация запуска и конфигурация покрытия. Изменение покрытия web может потребовать обновления `web/package.json` и корневого `package-lock.json`. У workflow есть зависимости от Go/Node, реестра Buf и Docker на раннере. Изменение выполняется отдельной веткой, без открытия PR по решению владельца.

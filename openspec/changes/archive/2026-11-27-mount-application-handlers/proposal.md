# Подключить прикладные маршруты и жизненный цикл к bootstrap

Issue MoloTeam/MoloTalk#26. Снимает D1 для подключения handlers в #9 и для внутреннего транспорта #31.

## Why

`platform/bootstrap` и `platform/httpserver` поднимают служебные пути, а прикладные Connect и WebSocket обработчики пока не имеют общей точки монтирования. Обёртка журнала должна прозрачно пропускать WebSocket upgrade и сохранять корреляцию.

## What Changes

- Добавить опциональную точку регистрации прикладных HTTP handlers к существующей точке сборки.
- Повесить на этот путь общие request ID и журнал. Подтвердить Connect и WebSocket upgrade на реальном loopback.
- Определить управляемый старт, завершение и cleanup при отмене либо ошибке, включая делегирование остановки долгоживущих подключений владельцу транспорта.
- Сохранить liveness каркаса и существующую семантику readiness. Активные службы поставляют проверки своих реально используемых зависимостей.

### Modified Capabilities

- `service-bootstrap` — опциональный HTTP mount и управляемый жизненный цикл подключённых ресурсов.
- `observability` — корреляция прикладных запросов и успешного upgrade.

## Impact

`backend/internal/platform/bootstrap`, `httpserver` и проверки Connect/WS. Существующие `cmd` остаются совместимыми, публичный wire и SQL сохраняются. Конкретные доменные handlers, доверие сервисов и жизненный цикл протокола Gateway входят в свои Issues.

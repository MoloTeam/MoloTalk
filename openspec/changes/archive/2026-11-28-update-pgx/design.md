# Дизайн обновления pgx

## Context

Проект использует Go 1.27 и pgx v5 для PostgreSQL. Базовый срез сообщает GO-2026-5004 и достижимость через fixtures. Эта информация задаёт проверку исправления. Вывод о полном текущем графе строится на свежем аудите.

## Goals / Non-Goals

- Поднять поддерживаемый релиз v5 до версии с исправлением, совместимой с Go проекта и выбранными testcontainers/goose.
- Сохранить работу migration и fixture контуров, обновить минимальный необходимый набор зависимостей.
- Настройка нового CI, миграции, смена драйвера и доработка продуктовых сценариев остаются отдельными работами.

## Decisions

1. Использовать новую стабильную версию существующего `github.com/jackc/pgx/v5` (MIT). Нижняя граница для GO-2026-5004 — v5.9.2. Конкретную версию выбрать после актуального аудита графа и проверки требований Go, учитывая другие advisories выбранной версии. Источник версии исправления — [база Go](https://pkg.go.dev/vuln/GO-2026-5004).
2. Установить версию в `backend/go.mod`, нормализовать транзитивный граф `go mod tidy`. Сравнить resolved version через `go list -m` и исход против свежего main, особенно если раньше сольётся Auth.
3. В отчёте разделить исчезновение GO-2026-5004 и другие сигналы аудита. Прогон с недоступной базой advisory считается непроверенным. Тесты PostgreSQL требуют доступного Docker/Testcontainers; успешная компиляция не заменяет интеграционный прогон.

## Risks / Trade-offs

Возможны обновление транзитивных библиотек, несовместимые настройки toolchain и изменение поведения подключения. Стабилизировать dependency graph на актуальном main, проверить чистую загрузку зависимостей, запуск migrate и fixture в PostgreSQL.

## Migration Plan

SQL и форматы данных сохраняются. Сравнить чистое создание и повторное применение миграций на уже заполненной базе. При регрессии остановить слияние и выбрать другой совместимый исправленный релиз.

## Open Questions

Конкретная версия и остаточные advisory определяются перед реализацией по действующим источникам и тестам.

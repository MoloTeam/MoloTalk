# Участие в разработке MoloTalk

## GitHub Flow

`main` — единственная долгоживущая ветка. Прямые коммиты в неё запрещены. Все изменения вносятся через pull request (PR), который одобряет минимум один участник команды, отличный от автора.

## Жизненный цикл карточки

1. **Создайте issue.** Укажите модуль, требования FS, разделы HLD и проверяемые критерии готовности. Используйте [шаблон задачи](.github/ISSUE_TEMPLATE/01-task.yml).
2. **Создайте ветку от актуальной `main`.** Формат имени — `<тип>/<номер-issue>-<кратко>`, например `feat/6-api-contracts` или `feat/7-web-skeleton`. Допустимые типы веток — `feat`, `fix`, `refactor`, `test`, `docs`, `ci`, `chore`.
3. **Подготовьте предложение OpenSpec, если оно нужно для карточки.** Сделайте это до реализации. Для работы с агентом действует обязательный цикл планирования и одобрения из [AGENTS.md](AGENTS.md).
4. **Реализуйте изменения** в ветке карточки.
5. **Проведите самопроверку.** Проверьте критерии карточки, сборку, запуск, затронутую функциональность и результаты доступных проверок CI. Для изменений логики добавьте модульные тесты. Зафиксируйте команды и результаты проверки для PR.
6. **Откройте PR в `main`.** Заголовок напишите на английском, описание — на русском по [шаблону PR](.github/PULL_REQUEST_TEMPLATE.md). Свяжите PR с issue через `Closes #<номер>` в описании. Заполните ID требований FS, разделы HLD и шаги проверки. Для служебного PR без прямой связи с FS укажите `—` и объясните причину.
7. **Пройдите ревью.** Внесите правки по замечаниям и получите одобрение другого участника. Участники команды берут на себя и авторство, и ревью.
8. **Влейте PR через Squash and merge.** Используйте заголовок PR как сообщение итогового коммита.
9. **Удалите рабочую ветку** после слияния.

## Коммиты и заголовки PR

Оформляйте коммиты и заголовки PR по [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/). Формат — `<тип>[(<область>)]: <краткое описание>`. Область необязательна. Примеры заголовка PR: `feat(web): add client skeleton with Caddy SPA delivery`, `docs: add contribution guidelines`.
